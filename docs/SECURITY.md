# Security model

Harness Arena runs other people's harness repositories against other people's code repositories, using
CLIs that hold the user's own provider sessions. Treat everything that enters the system as adversarial.

## Assets

1. Provider credentials held by the agent CLIs (Claude Code, Codex, Gemini CLI, OpenCode).
2. The user's source code, working tree, and environment variables.
3. The user's Arena account and device tokens.
4. The integrity of published battle results and ratings.
5. The web server and other tenants' data.

## Non-negotiables

- **Arena never reads, copies, proxies, or uploads provider credentials.** Adapters spawn the official CLI and let it authenticate itself. No adapter reads `~/.claude/.credentials.json`, keychains, `~/.codex/auth.json`, or Google tokens. `validate()` may only ask the CLI itself (for example `--version`).
- **The web server never executes harness or repository code.** GitHub import inspects repositories through the GitHub REST API (tree listing + file contents), never by cloning or running anything.
- **The user's checkout is never modified.** Arena keeps its own bare mirror and gives every run a detached git worktree of that mirror.
- **No model spend on Arena's behalf.** Nothing in this repository holds a provider key or calls a model API. Verified cloud battles are designed in the data model and deliberately not hosted.

## Threats and controls

| Threat                                                            | Control                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Malicious `arena.yaml` (install/prepare/cleanup commands)         | Commands are printed verbatim and require explicit trust (`--trust` or interactive approval) before anything runs. Untrusted harnesses with commands never execute. Commands run in the harness checkout or the workspace, never in the user's repository.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Shell injection through task text, file names, or manifest values | Adapters build fixed argv arrays and deliver the prompt on **stdin**. No provider CLI is ever invoked through a shell with interpolated text. Test, install and prepare commands authored by the user or the harness run through the shell by design and are shown as such; they go through one helper (`shellInvocation`) that hands `cmd.exe /d /s /c` an already-quoted line with `windowsVerbatimArguments`, so a command containing a double quote runs as written instead of being silently mangled into an exit 0.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Binary or shell hijack through the invocation directory           | Agent CLIs are spawned inside a battle workspace the harness and the agent can write to, and Windows resolves a bare command name against the current directory before `PATH`. Arena resolves every command to an absolute path itself, searching absolute `PATH` entries only (empty and relative entries are skipped), and takes the shell for user-authored command lines from `ComSpec` or `%SystemRoot%\System32\cmd.exe`, never from a relative name.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Path traversal / symlink attacks in harness files                 | Containment is textual **and** filesystem-checked. `applyHarness` resolves every source path, rejects `..` and absolute paths, refuses anything outside the harness root, skips symlinks (never follows). On the way out it refuses a destination whose path crosses a symbolic link or junction inside the workspace, requires `realpath(dirname(dest))` to stay inside `realpath(workspace)`, and opens each file with `wx` so an existing entry is never followed; a refused or unwritable file is skipped with a warning and listed in `skippedFiles` instead of aborting the apply. A `/tree/<ref>/<subdir>` harness subdirectory that is a link out of the checkout is rejected at resolution with `path_escape`, and the file source it would have read refuses a root that realpaths outside the checkout. Fake-adapter fixtures are held to the same containment rule: every component of a fixture's target path is `lstat`-ed under the workspace and a symlink or junction refuses the whole operation. |
| Repository git hooks                                              | Every git invocation Arena makes sets `core.hooksPath` to an empty directory; hooks in the mirrored repository never run during clone, fetch, worktree checkout, or diff.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Dependency lifecycle scripts                                      | Running the task may execute `npm install` and similar as part of the agent's work; that is inherent to the task and runs inside the disposable worktree. The report discloses every command the harness declared.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Secret exposure in telemetry                                      | The redactor scrubs known token formats, `KEY=value` secrets, PEM blocks, bearer headers, URL userinfo credentials, and every environment value that looks like a secret before events, the diff, the final response, the raw provider log, the record or the report touch disk or the network. Environment variable values are never uploaded; only the names Arena added appear in the invocation disclosure.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| BYOK keys supplied in the battle spec                             | `competitors.<side>.agent.env` and a harness's `agentConfig.<agent>.env` reach the child process and nothing else: the stored record, the report and every upload keep the names and replace the values with `[REDACTED]`, whatever `privacy.redact` says. The uploader repeats the substitution itself rather than trusting the engine to have done it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Credential theft by a harness                                     | Harness code runs with the user's privileges (unavoidable in local mode) and is disclosed beforehand. Local mode is for harnesses the user chooses to trust; verified cloud mode is the answer for untrusted harnesses and is designed but not hosted.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Event poisoning / oversized logs / DoS on ingest                  | Zod validation on every event, per-string (16 KB), per-event (64 KB), per-batch (500) and per-battle (50,000) caps, body size limits, per-token rate limiting, and append-only sequence numbers. Invalid events are rejected and counted, never stored.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Malicious terminal output (ANSI, control chars)                   | ANSI escapes are stripped before rendering; the report and the web app render text only (no HTML injection paths: React escaping, `textContent` in the static report, JSON embedded with `<` escaped).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| XSS through agent output on the web                               | No `dangerouslySetInnerHTML`; markdown docs are rendered without raw HTML; strict `Content-Security-Policy`, `X-Frame-Options: DENY`, `nosniff`, referrer policy.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Cross-tenant access                                               | Every battle query is scoped by visibility and owner; private battles are only readable by their owner's session or device token. Device tokens are hashed at rest, revocable, and scoped.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Device token read off the local machine                           | `ARENA_HOME/config.json` is written with mode `0600`, which applies **on POSIX only**. Windows has no POSIX modes, so the `chmod` is attempted and its failure ignored, and the file relies on the per-user ACL it inherits from the home directory. Tokens are revocable from the account page.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Websocket/SSE abuse                                               | The stream endpoint is read-only, visibility-checked, heartbeat-bounded, and backed by database polling (no shared in-memory fan-out to abuse).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Unsafe archive extraction                                         | Arena never extracts archives. Harnesses and repositories are obtained with `git clone`; the web inspects through the API.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Interruption / crashes                                            | Process trees are killed on abort or timeout (`taskkill /T` on Windows, process-group kill elsewhere); records are flushed after every phase; worktrees are removed in `finally`; `arena doctor` reports and removes orphaned workspaces.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

## Leaderboard integrity

| Threat                                       | Control                                                                                                                                                                                                                                                                                         |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fabricated or edited local results           | Community results are self-reported by design and labelled as such everywhere; they never enter the verified pool. Every rated battle keeps its full record, provenance (agent version, model, harness commit, repository commit, evaluator version) and integrity flags for anyone to inspect. |
| Self-play, duplicate uploads                 | Same harness commit on both sides is blocked; a fingerprint over task, commits, agents, harness versions and evaluation spec blocks a second rated copy of the same matchup.                                                                                                                    |
| Mutable harness URL inheriting an old rating | Every rating event is pinned to a `harness_versions` row (exact commit); a GitHub/git harness without a resolved commit is never rated.                                                                                                                                                         |
| Deleted or modified tests                    | Changed files under test paths are detected from the diff signals: deletions block, modifications warn and are shown. Task assertions can pin test files with `diff-not-touches`.                                                                                                               |
| Tiny samples presented as rankings           | Ranked lists require 10 decided battles and a deviation under 120; insights and experiment conclusions carry their n and stay silent below the thresholds.                                                                                                                                      |
| Benchmark drift                              | Pack versions are content-addressed; a ranked result points at an immutable version id.                                                                                                                                                                                                         |
| Cross-account catalogue edits                | A battle upload may discover a harness or a pack but never rewrites an existing row's identity; only the import flow (harness) or the owning account (pack) can.                                                                                                                                |

## Local-mode disclosure

Before a battle runs, the CLI prints for each side: the agent binary, the exact argv (never the prompt body), the environment variable **names** Arena added, the harness files that will be copied, and any commands the harness declared. Non-interactive runs must pass `--trust` to execute declared commands.

## Reporting a vulnerability

Open a private security advisory at <https://github.com/ucsandman/harness-arena/security/advisories/new> (on GitHub: the repository, then Security, then "Report a vulnerability"). That form is the only reporting channel; no package in this repository publishes a maintainer address. Please do not file public issues for credential or sandbox-escape problems.
